# yt6video クラウド環境対応 検証（2026-10-03）

## 実施内容
- `setup_cloud.sh` で新規の環境を構築（約20秒）→ 置き換えなしの本番コマンドで6本を生成（約5分30秒）
- 音声は edge-tts への接続失敗（403）を検知し、自動でオフライン音声（pyopenjtalk）に切り替わった

## 結果
- 6本とも完成（各73〜86秒）、無音スライド0、ナレーション網羅チェック問題なし
- report.txt の音声欄は「pyopenjtalk（オフライン音声）」と正しく記録
- 音声の実体確認：EP0冒頭8秒のスペクトログラムに、音節ごとの区切りと倍音構造（人の声の特徴）を確認
- `--tts edge` を指定し、接続できない場合はエラーで止まる（勝手に切り替わらない）ことを確認

## ネットワーク許可後の再検証（www.youtube.com / speech.platform.bing.com を許可）
- タイトル取得：**成功**（例: "Inside the Mind of a Master Procrastinator | Tim Urban | TED"）
- 字幕取得：**失敗**。YouTube がクラウドのIPをロボット扱いし google.com/sorry（確認画面）へ転送。yt-dlp も "Sign in to confirm you're not a bot"。
  → ネットワーク設定では解決しない。YouTube 側の対策。
- edge-tts：**失敗**。プロキシは通過しているが、Microsoft 側が WebSocket 接続を 403 で拒否（edge-tts 最新版 7.2.8 でも同じ）。
  → 既定の auto ではオフライン音声に自動で切り替わるため、動画の生成は止まらない。

## 結論
- クラウド環境だけで完結するのは「文字起こしテキストを渡す → 6本の動画（オフライン音声）」まで。
- URLだけから字幕を取るには、PCで実行するか、別の取得手段（例: Gemini API に YouTube URL を渡して文字起こしさせる）が必要。
